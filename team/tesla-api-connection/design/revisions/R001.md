# R001: Verification script for MVP Fleet API GETs

Decisions (PO, decision round 1, 2026-10-04):
- Q1 = A: a read-only, owner-run script. No credentials are shared with agents (CLAUDE.md §12: agents never call real Tesla endpoints).
- Q2 = only the four required GETs (products, site_info, live_status, calendar_history kind=energy). These cover the MVP: site discovery, timezone/hardware/tariff, live flows, and daily backfill (CLAUDE.md §5).
- Q3 = yes: anonymized fixtures go in `fixtures/fleet-api/`, and the PO looks them over before they're committed.
- Q4 = yes: about 5 requests per run (1 token refresh + 4 GETs) is acceptable. Wake limits apply only to vehicles (energy sites don't sleep), so they're irrelevant here.

Changes:
- The SPEC defines `scripts/verify-tesla-gets.mjs` and its pure helpers.
- Tests use `node:test` rather than Vitest. The repo has no test runner yet, and stdlib avoids adding a dependency to a layout that the Phase 1 monorepo scaffold will replace. These tests move to Vitest when that scaffold lands.
- The crypto helpers are duplicated inside the script because `src/lib/crypto.ts` depends on the `~/env` alias, which a plain `.mjs` file can't import.
